## What is Data Export

The Data Export app exports bibliographic (instance), holdings and authority data from FOLIO as MARC 21 (.mrc) files, and — since Trillium — Linked Data instances as JSON Lines (.json) via the Default linked data export job profile (MDEXP-885). Staff upload a .csv file of UUIDs or a .cql file containing a CQL query, select a job profile, confirm the record type (custom profiles only, UIDEXP-413), and the system generates a downloadable file logged in the Logs pane. Exports can also be triggered from the Inventory and MARC Authority apps via the Actions menu (quick export), where the UUID .csv downloads immediately while the .mrc file is generated asynchronously and logged in Data Export. Job and field mapping profiles are configured in Settings > Data export and can be locked/unlocked by authorized users (UXPROD-2708, Trillium).

## Key Terms

| Term | Definition |
|---|---|
| Job profile | Top-level export configuration that links to one field mapping profile. Entry point for running an export. |
| Field mapping profile | Defines record types, output format, transformations, fields suppression and "Suppress 999 ff" for the output. |
| Default profile | System-provided profile (`"default": true`, Updated by "System Process" — Cypress C380470). Always locked; cannot be unlocked, edited or deleted (MDEXP-894, MDEXP-898/899). |
| Lock profile | Checkbox on job/mapping profile create/edit/view forms (en.json `locked` = `Lock profile`). Locked profile is read-only (duplicate only) until an authorized user unlocks it (UIDEXP-414/415). |
| Transformation | A mapping rule inside a field mapping profile that routes an Instance/Holdings/Item field to a MARC field, indicators and subfield. |
| Fields suppression | Mapping profile setting listing MARC tags (three digits, comma-separated) excluded from the output (UIDEXP-361/375). |
| Suppress 999 ff | Mapping profile checkbox (en.json `suppress999ff`; schema `mappingProfile.suppress999ff`) — omits the 999 ff field from the output. |
| SRS | Source Record Storage. Instances with SRS records export their full underlying MARC; FOLIO-native instances get MARC generated on the fly from default mapping rules. |
| Linked Data export | Export with "Default linked data export job profile"; output format `LINKED_DATA`, file `.json` in JSON Lines (one resource graph per line) (MDEXP-884/885). |
| Quick export | Export triggered from Inventory (Actions → Export instances (MARC)) or MARC Authority (Actions → Export selected records (CSV/MARC)). UUID .csv downloads immediately; .mrc appears asynchronously in Data Export logs (`POST /data-export/quick-export`). |
| Running accordion | Accordion in the Jobs pane that shows in-progress export jobs with a progress bar. |
| View all | Button on the Logs pane that opens the full log history with search and filter capabilities (replaces the 25-record default view). |
| (deleted) notation | Suffix appended to the Job profile name in Logs / Consortium manager logs after the job profile was deleted (UIDEXP-419, Cypress C1045408). |
| Purge window | Authority records set for deletion stay exportable only until they are purged; after that they are not found and cannot be exported by any profile (MDEXP-680; Cypress C446016). The "7 days" figure is (unverified) — see Known Gaps. |

## Record Hierarchy / Architecture

```
Job Profile  (entry point — what to run; locked flag)
  └── Field Mapping Profile  (what fields to include and how to transform; locked flag)
        ├── Record types (schema enum: INSTANCE, HOLDINGS, ITEM, AUTHORITY, SRS, LINKED_DATA)
        │     UI checkboxes for custom profiles (at least one required):
        │     ├── Source Record Storage (entire record)   [exports full SRS MARC; cannot be combined with Instance]
        │     ├── Inventory instance (selected fields)    [generated on-the-fly]
        │     ├── Holdings                                [appended to MARC output]
        │     └── Item                                    [appended to MARC output]
        ├── Output format (schema enum: MARC, LINKED_DATA — LINKED_DATA only in the default LD profile)
        ├── Transformations  (MARC field/indicator/subfield mappings)
        ├── Fields suppression  (MARC tags to exclude; comma-separated 3-digit codes)
        └── Suppress 999 ff  (boolean)
Job execution (log row) → status, progress {total, exported, failed, duplicatedSrs}, exportedFiles[], error logs
```

Sources: mod-data-export `swagger.api/schemas/profiles/mappingProfile.json`, `recordTypes.json`, `jobExecution.json`; en.json `mappingProfiles.srs.info`, `error.mappingProfile.invalidSrsRecordTypeCombination`.

## Lifecycle / Workflow

### Export Job Lifecycle

| Phase | UI representation |
|---|---|
| File uploaded | "Select job profile to run the export" pane — list of job profiles with search and a `Status` column (`Locked` / empty); deleted profiles are not listed (UIDEXP-419, Cypress C1045408) |
| Profile chosen | "Are you sure you want to run this job?" modal. Default profile → no record-type dropdown; custom profile → "UUIDs provided for this export" dropdown (Instances / Holdings / Authorities) is required (UIDEXP-413) |
| Running | Progress bar under "Running" accordion; "Triggered by {userName}" (same user name format as "Run by", incl. users without first name — UIDEXP-422, Cypress C1273176) and "Job profile: {jobProfile}" |
| Completed | Row in Logs with Status "Completed"; File name is a hyperlink |
| Completed with errors | Row with Status "Completed with errors"; File name is a hyperlink; click row → per-record errors |
| Fail | Row with Status "Fail"; File name NOT a hyperlink; click row → error messages |
| Profile later deleted | File name becomes read-only text, Job profile shows `<name> (deleted)`, error log no longer opens (MDEXP-898, UIDEXP-419, Cypress C1045408) |

### Export Job Statuses

| Status (UI, en.json `jobStatus.*`) | API value | Meaning |
|---|---|---|
| `New` | NEW | Job created, file not yet processed |
| `In progress` | IN_PROGRESS | Shown in the Running accordion, not in Logs |
| **`Completed`** | COMPLETED | All records exported; file downloadable |
| **`Completed with errors`** | COMPLETED_WITH_ERRORS | Partial export; file downloadable; per-record error log |
| **`Fail`** | FAIL | No records exported; no file; click the row (not the filename) to see errors |

Hung jobs: `POST /data-export/expire-jobs` (timer) fails jobs with "Job was expired: no updates for more than 1 hour" (mod-data-export `ErrorCode.java` ERROR_JOB_IS_EXPIRED).

### Profile Lifecycle (Trillium R1 2026 onward — replaces the "used profile cannot be edited/deleted" model)

| Profile state | User with `Settings - UI-Data-Export Settings - Edit` | User with `Settings - UI-Data-Export Settings Lock - Edit` |
|---|---|---|
| Default (job or mapping) | Duplicate only (instance/holdings defaults); Actions menu hidden for authority and Linked Data defaults | Same — defaults cannot be unlocked or edited |
| Custom, locked | Lock checkbox checked + read-only; Actions = Duplicate only | Edit, Duplicate, unlock (uncheck Lock profile), then delete |
| Custom, unlocked | Edit, Duplicate, Delete; Lock checkbox read-only unchecked | Edit, Duplicate, Delete, lock |
| Duplicate of a locked profile | New profile is unlocked | New profile is unlocked |
| Unlocked job profile used in exports | Can be deleted — modal warns that export files will be permanently deleted | Same |
| Unlocked mapping profile referenced by a job profile | Cannot be deleted — "Cannot delete mapping profile" modal lists job profiles | Same |

Sources: UIDEXP-414, UIDEXP-415, UIDEXP-417, UIDEXP-418, UIDEXP-424, UIDEXP-425, MDEXP-894, MDEXP-895, MDEXP-898, MDEXP-899; Cypress C1003543, C1030053, C1030056, C1030057, C1045406, C1045407, C1045995, C1046001–C1046005, C1046010, C15825, C15828; docs `settings_data_export.md` "Locking and unlocking profiles".

## Status Values

### Export Job Status
UI: `Completed`, `Completed with errors`, `Fail` (Logs); `In progress` (Running accordion); `New`. API: `NEW`, `IN_PROGRESS`, `COMPLETED`, `COMPLETED_WITH_ERRORS`, `FAIL` (mod-data-export `jobExecution.json`).

### Profile Status (Settings lists and Select job profile pane)
`Locked` or empty (unlocked). API: `locked` boolean + `lockedBy` (user UUID) + `lockedAt` (timestamp) on `jobProfile.json` / `mappingProfile.json`; newly created profiles return `locked == false` and no `lockedAt`/`lockedBy` (Karate `export-locked-job-profile.feature`).

## Common Verification Patterns

> Copy these into expected results. They reflect how the team actually writes assertions for this area.

### Pattern 1: Successful export with Edit capability (custom job profile)

```
Action:   Navigate to Data export → click "or choose file" in Jobs pane → upload .csv file
          → "Select job profile to run the export" pane opens → click a CUSTOM job profile
          → "Are you sure you want to run this job?" dialog → select record type from
          "UUIDs provided for this export" dropdown → click "Run"
          (with a DEFAULT job profile the dropdown is absent — click "Run" directly; UIDEXP-413)
Expected: Progress bar appears under "Running" accordion
          After job completes: new row in Logs table with:
            Status = "Completed"
            Job profile = "<selected job profile name>"
            Total = Exported (same value, no failures)
            File name is a hyperlink
          Clicking the filename hyperlink downloads the .mrc file
```

### Pattern 2: Export with duplicate SRS records (Completed with errors)

```
Action:   Run export for instances where at least one instance has multiple SRS records
Expected: Status = "Completed with errors"
          Failed column shows count: "{n} duplicate(s)"
          Clicking the row (not the filename) opens error log:
            ERROR Instance with HRID: {hrid} has following SRS records associated: {uuid1}, {uuid2},...
          Each affected instance has a separate error entry with UUID, HRID, Title, and link to record
          File name IS a hyperlink (partial export was generated)
```

### Pattern 3: View-only capability — export blocked

```
Action:   Log in with only Data - UI-Data-Export - View capability set
          → Navigate to Data export app
Expected: "Drag and drop" area in Jobs pane is disabled (cannot upload files)
          "Logs" pane is displayed with the table and "View all" button (enabled)
          Settings app is NOT available in the app menu
          Only "Data export" app is available
```

### Pattern 4: Quick export from Inventory (multi-record)

```
Action:   Inventory → select instance checkboxes → Actions → "Export instances (MARC)"
Expected: .csv file downloads immediately to local machine
          File name format: QuickInstanceExport{YYYY-MM-DD}T{hh_mm_ss}….csv
          .csv contains UUIDs of selected instances without duplicates
          In Data export app: new row added to Logs with:
            File name = quick-export-{job ID}.mrc
            Status = "Completed"
            Job profile = "Default instances export job profile"
            Run by = current user's username
          Clicking filename hyperlink downloads .mrc file
```

### Pattern 5: Locked / deleted job profile (Trillium+)

```
Action:   Settings > Data export > Job profiles → open a locked custom job profile as a user
          with only "Settings - UI-Data-Export Settings - Edit"
Expected: "Lock profile" checkbox is checked and disabled; Actions menu offers only Duplicate

Action:   As a user with "Settings - UI-Data-Export Settings Lock - Edit": Actions > Edit →
          uncheck "Lock profile" → Save & close → Actions > Delete → Delete
Expected: Toast "Job profile <name> has been successfully edited", then the delete modal reads
          "The job profile <name> and all files created by export jobs that used this profile
          will be permanently deleted." (profile used in exports) → toast
          "Job profile <name> has been successfully deleted"
          Data export > Logs: Job profile = "<name> (deleted)", File name is plain text,
          clicking a Fail / Completed with errors row does not open the error log;
          the profile is absent from "Select job profile to run the export" and the View all
          "Job profile" filter
```

## Key Business Rules for Test Cases

1. **Locked job profile cannot be edited or deleted; an unlocked job profile can be deleted even if it was used in exports** — deletion of a used profile removes all its export files, keeps the log rows, makes the File name non-clickable, appends `(deleted)` to the Job profile name and removes the error logs of Fail / Completed-with-errors jobs; the linked mapping profile is not deleted. *(Corrected 2026-11-24: the earlier "used job profile → Edit/Delete disabled" rule was replaced in Trillium.)* (MDEXP-898, UIDEXP-417, UIDEXP-419; Cypress C1030053, C1045408; Karate `export-deleted-job-profile.feature`)
2. **Field mapping profile referenced by a job profile cannot be deleted** — `Cannot delete mapping profile` modal lists the linked job profiles, Close is the only button; delete (or relink) the job profiles first. An unlocked referenced mapping profile **can** be edited. (UIDEXP-418, MDEXP-899; Cypress C15825, C15826)
3. **Field mapping profile requires a name, an output format and at least one FOLIO record type checkbox** — saving without them returns the required-field validation error. (ui-data-export `src/settings/MappingProfiles/MappingProfilesForm/MappingProfilesForm.js` `validate`: `required(name)`, `required(outputFormat)`, `requiredArray(recordTypes)`; error text not asserted)
4. **Custom profiles output MARC only; Linked Data (JSON) output exists only through the Default linked data export job profile** — mapping profile `outputFormat` enum is MARC / LINKED_DATA. *(Corrected: previously "output format is always MARC".)* (mod-data-export `mappingProfile.json`; MDEXP-885)
5. **Default authority export profile rejects records set for deletion** — each such record produces `Authority record {UUID} is set for deletion and cannot be exported using this profile`; export may still be "Completed with errors" if some records were valid. (ErrorCode.java; Cypress C446010, C446011)
6. **Deleted authority export profile rejects non-deleted records** — `This profile can only be used to export authority records set for deletion` per record. (en.json `error.onlyForSetToDeletion`; Cypress C446012, C446014)
7. **Records past the 7-day purge window → "Record not found"** — even the correct deleted profile cannot export purged records; individual error per record. (Cypress C446016; MDEXP-680; the "7 days" figure is (unverified))
8. **Record type is chosen only for custom job profiles** — with a default profile the "Are you sure" modal shows no "UUIDs provided for this export" dropdown and the record type/output format come from the profile; with a custom profile the type must be selected and a wrong type causes systematic failures. (UIDEXP-413, MDEXP-886)
9. **Quick export: UUID .csv is immediate; .mrc is async** — .csv arrives in browser immediately; `quick-export-{ID}.mrc` appears only in Data Export logs. (cases; Cypress C446170)
10. **Logs show 25 most recent by default; "View all" shows complete history** — logs are not deleted by the UI; search and filter available only in View all. Exceptions: `DELETE /data-export/job-executions/{id}` removes a row (C446048) and deleting a job profile removes its files (rule 1). (TestRail C380757 `limit: 25`; docs `_index.md`)
11. **Fail status = no file generated** — file name in the log row is not a hyperlink; clicking the row itself opens error details (not so in Consortium manager logs, where the row does not open). (TestRail C468248, C566502; Cypress C350973)
12. **Completed with errors = partial file exists** — file is downloadable; per-record error details available by clicking the row. (TestRail C468248, C468204, C476789)
13. **Transformation validation: Field = exactly three digits; Subfield must begin with `$`** — e.g. `$a`; invalid input triggers `Please check your input`; empty indicators display as blank/backslash consistently (UIDEXP-384, UIDEXP-385). (github; Cypress C543742)
14. **FOLIO-native instances generate simplified MARC** — less complete than SRS MARC; note in expected results when the instance source is FOLIO vs MARC. Instances with source LINKED_DATA export their SRS record with MARC profiles. (MDEXP-807; TestRail C468204/C1301745 "for FOLIO Instances simplified MARC is generated on the fly")
15. **Large exports generate a .zip archive** — default slice size is 100,000 per file; configurable per tenant via `POST /data-export/configuration { "key": "slice_size", "value": "100000" }`; .zip entries must carry the output-format extension. (cases — C431148; MDEXP-909; Cypress C432316)
16. **Export jobs run asynchronously and in parallel, also across tenants** — each shows its own progress bar. (TestRail C446054; MDEXP-687) The earlier claim "small jobs are not queued behind large jobs" is (unverified) — see Known Gaps.
17. **Download link for export files does not expire** — files from past export jobs remain downloadable unless the job profile was deleted (then the download returns 500 and the link is disabled); past-date downloads give no "token expired" error. (TestRail C468248; MDEXP-898; Karate `export-deleted-job-profile.feature`)
18. **Only .csv or .cql file extensions are accepted** — any other extension triggers the "Invalid file" modal. (cases + github; Cypress C9292)
19. **Sorting is preserved across page reload (F5)** — including with active filters on the View all page; filters keep the sort, Reset all restores Ended running descending. (TestRail C387482, C380757; Cypress C387482, C380757)
20. **"Job profile" filter (View all) shows only profiles used in at least one export and not deleted** — unused and deleted profiles do not appear; API: `job-profiles?used=true`. (cases; UIDEXP-419; Cypress C1045408, C411724)
21. **"Errors in export" filter: Yes includes "Completed with errors" AND "Fail"; No includes only "Completed"; both checked = all three statuses; options read `No` / `Yes`** (TestRail C404374; Cypress C404374)
22. **"Run by" column sort order differs by view** — View all page: FirstName, LastName (C387482); landing page: LastName, FirstName (C380757). (TestRail)
23. **No system-defined "Data Export" or "Data Export Admin" authorization roles exist** — must be created manually by assigning capability sets. (cases — C877101, C877107)
