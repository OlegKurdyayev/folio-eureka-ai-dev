## What is Licenses

The Licenses app (ERM, team K-Int/Bienenvolk + Thunderjet QA) manages legal contracts and terms of use for licensed content. It tracks license metadata, terms (custom properties), organizations, internal contacts and attached documents (core and supplementary). Licenses can have amendment child records and are linked from agreements (Agreements app). Since Trillium, licenses can be protected by acquisition units (ERM-3908, ERM-3910–ERM-3916).

## Key Terms

| Term | Definition |
|---|---|
| License | Contract and terms-of-use record governing access and permitted actions |
| Amendment | Child record representing a modification to a parent license; inherits the parent's acquisition units (docs ERM/Licenses) |
| Term | License custom property (`/licenses/custprops`) — Text, Integer, Decimal, Date, Pick list, Pick list (multi-select) |
| Primary / optional term | Primary = always shown on every license; optional = added per license (Settings > Licenses > Terms) |
| Core document | Primary legal file/link/location attached to a license (no category — ERM-2366) |
| Supplementary document | Additional supporting document with a category |
| Licensor | The organization with role `licensor`; only one per license (en.json `errors.multipleLicensors`) |
| Pick list | Refdata category (`/licenses/refdata`) backing a dropdown or a Pick list term |
| Agreement link | Relationship from an agreement to one or more licenses (`/licenses/licenses/{id}/linkedAgreements`) |
| Acquisition unit | Access-control unit restricting View/Create/Edit/Delete for non-members (mod-licenses access-control library, ERM-3908) |

## Record Hierarchy / Architecture

```
License
  ├─ License information (Name, Type, Status, Start/End date, Open ended, Description, Alternative names)
  ├─ Acquisition units (license only; amendments inherit)
  ├─ Internal contacts (Users app records)
  ├─ Organizations (Organizations app records; roles from pick list LicenseOrg.Role; one Licensor)
  ├─ Core documents
  ├─ Terms (primary + optional; grouped in one accordion per term category)
  ├─ Supplementary documents
  ├─ Amendments
  │    └─ Amendment information / Core docs / Terms / Supplementary docs / Tags
  ├─ Agreements linked to this license (read-only, from mod-agreements)
  ├─ Notes, Tags
  └─ Connected tasks/jobs pane (Umbrellaleaf, plugin `task-list`, ERM-4156)
```

## Lifecycle / Workflow

| Status | Description |
|---|---|
| Active | License is currently in use (default search filter) |
| Expired | License is no longer active |

> Status and Type are tenant pick lists (`License.Status`, `License.Type`), so more values may exist (docs ERM/Licenses). There is no enforced transition graph: any status can be set on edit. Amendments have their own status (`amendments.view.status` = `Amendment status`); on an agreement, each amendment also gets an agreement-side link status (`prop.amendmentLinkStatus` = `Amendment link status`).

### License Term "Name" field validation (C1385636, C1347204, ERM-3465, ERM-4101)
- Must **start with a letter** and contain only **letters, digits, or underscores** (no spaces — a trailing space also fails, C1385636 step 7 — punctuation or symbols).
- Unicode letters are valid: `Property_汉`, `test李` succeed (C1385636, C1347204). The rule is "letter first, then letters (incl. Unicode)/digits/underscore", not ASCII-only.
- Empty Name: field highlighted red, `Please fill this in to continue` (C1385636; ERM-4101 "already implemented").
- Non-empty invalid Name: en.json master and ERM-4101 ACs say `The name must start with a letter, and can only contain letters, numbers, and underscores.`; C1385636 still expects the generic `Please fill this in to continue` — see Known Gaps.
- API (`POST`/`PUT /licenses/custprops`) rejects invalid names with 4xx and message `Custom property name must start with a letter and contain only letters, digits or underscores` (C1347204). The allowlist applies only to new/changed names, not to existing data (ERM-3465 comment).
- Duplicate Name: API returns 422 `License term name must be unique. A license term with the name {name} already exists.` (ERM-3229; the pick-list-term 500 was fixed in ERM-3230, Sunflower); the UI must show it (ERM-3977, Trillium) via `There was an error saving term: {error}`.
- (i) tooltip next to Name, en.json `terms.help.name`: `A term 'name' is used when outputting the term data in a machine readable format intended to be used by external systems or programs that access the term data. It is not intended to be displayed to users (staff or patrons). It should be a short string which must start with a letter, and can only contain letters, numbers, and underscores. Changes to the term name will affect any external systems using license term data and changes should not be made without consulting those responsible for relevant external systems and software.`

## Document Filter Builder (Search & filter — "Core documents" / "Supplementary documents" facets)

> Confirmed via C422210 (Filter amendments by core documents); same builder for License search (C422201, C422203) and amendments supplementary documents (C422211).

- Trigger: expand the "Core documents" (or "Supplementary documents") filter accordion → `Edit document filters` → popover with a `Document filter 1` card.
- Each card: **Attribute** (`Name`, `Note`, `Physical location`, `URL`, `Content type`, `File name`), **Operator** (`Is`, `Contains`, `Does not contain` — en.json `operator.*`), free-text **Value**, plus `Add rule`. Focus moves to the new rule's Attribute field after `Add rule` (ERM-3899).
- `Save & close` stays disabled until at least one complete rule (Attribute + Operator + Value) exists.
- **Rules within one card are AND** ("AND" label prepended); **multiple cards (`Add filter`) are OR**.
- Each card has its own trashcan. Filter state persists when reopening the popover.
- Test both "Contains" and "Does not contain", and confirm "Is" requires an exact match.

## Acquisition Units (Trillium+, ERM-3908–ERM-3916, section 91698)

- Assigned on the license only; amendments inherit the parent's units (docs ERM/Licenses; C1028993 shows them on the amendment view).
- Edit form: `Acquisition units` accordion open by default, first after Alternative names; typedown lists only units the user may assign (units with protectCreate = false or units the user belongs to); each entry shows name · description · restricted actions; selected units appear in an MCL (Name, Description, Access, Remove) with trashcan tooltip `Remove {acquisition unit name}` (ERM-3910, C1028998).
- View: `Acquisition units` accordion first, badge with count, MCL Name (sortable, default ascending), Description, Access; hidden when no units are assigned — removing the last unit makes it disappear (ERM-3911, C1029000, C1028998).
- A unit restricts an action only for non-members. Membership in **any one** of the license's units is enough: C1029002 (member of both) and C1029004 (member of only the unit restricting Create/Edit/Delete, while the other unit also restricts View) both get full Edit/Duplicate/Delete on the license and its amendments.
- View restriction: the license and its amendments do not appear in search (C1028988); opening a protected license by URL shows an access error, not an empty record (ERM-3962).
- Actions menu: Edit/Delete shown greyed out and inactive when restricted; `Add amendment` inactive when the license can't be edited (ERM-3913); amendment Edit/Delete greyed out (ERM-3914, ERM-3961); amendment Duplicate inactive when `canCreate` is false (ERM-3979).
- Backend: cloning a license/amendment the user cannot view returns 403 (ERM-3958, ERM-3960); expected message shape `PolicyRestriction.READ check(s) failed in access control` (ERM-3978).
- Filters: `Acquisition unit` filter on Licenses (after Type, before Organizations) and Amendments; first option `No acquisition unit` (ERM-3915, ERM-3916, C1028996, C1028997).
- Acq units can be switched off by environment variable; then no acq-unit UI and no acq-unit calls (ERM-3807; follow-up ERM-4076 still open).

## Pick Lists (C464319, C464320, C464329; ERM-1910, ERM-3709)

- `Settings > Licenses > Pick lists`: searchable table (`Category`, `# of values`); categories follow `{Entity}.{FieldName}` (e.g. `License.Type`, `License.Status`, `LicenseOrg.Role`) or are custom pick lists for Pick list terms.
- `New` adds an editable `Category` row; saving re-sorts alphabetically, `# of values = 0`, opens a 4th pane. Trashcan opens `Delete pick list category`.
- 4th pane `Pick list values`: `New` adds a `Label` row with `Save`/`Cancel`; values can be edited (pencil, aria `Edit value {label}`) and deleted (`Delete value {label}`). Editing changes only the label, not the stored value (docs Settings_licenses).
- New values are immediately selectable in the matching dropdown (e.g. `LicenseOrg.Role` → organization `Role`).
- With only `UI-Licenses Picklists - View`, `New` must be inactive (ERM-3709, Sunflower fix).
- Distinct from Term Types/Term Names.

## Key Business Rules for Test Cases

> One rule per line, source in parentheses.

1. A license needs `Name` (max 255 chars), `Type` and `Status` to save; all three are required fields. (LicenseFormInfo.js; cases — C762, C10993)
2. An amendment needs `Name` (max 255) and `Status`; Type is not on the amendment form. (AmendmentFormInfo.js)
3. On create, `Record created` and `Record last updated` are equal; after an edit only `Record last updated` changes. (cases — C762, C1330)
4. Checking `Open ended` disables End date and shows the clear-end-date warning; the end date is cleared on save — it is not a blocking error. (LicenseFormInfo.js, AmendmentFormInfo.js; en.json `warn.clearEndDate`)
5. End date must be strictly after Start date; the same date is rejected with `End date must be after the start date.` (LicenseFormInfo.js `startDate >= endDate`)
6. A badly formatted typed date blocks Save & close on the license form instead of clearing the date. (ERM-3298, ui-licenses 11.1.0)
7. Start and End dates are optional; validation fires only when populated. (ERM-3298)
8. Only one organization per license can have role Licensor. (en.json `errors.multipleLicensors`; LicenseFormOrganizations.js `uniqueRole="licensor"`)
9. The amendment view shows the parent license's primary organization as `Licensor`, or `Not set`. (AmendmentLicense.js; ERM-2420)
10. Internal contacts must be Users app records; free-text contacts are not possible. (cases + docs)
11. Organizations must be Organizations app records; one can be primary. (cases + docs)
12. Core document requires Name plus at least one of file, physical location or URL; core documents have no category. (cases + docs; ERM-2366)
13. Supplementary document requires Name, Category and at least one of file, physical location or URL. (cases + docs)
14. Primary terms always appear on every license and cannot be removed (value may be left blank / `Not set`); optional terms must be added per license. (docs ERM/Licenses)
15. Primary terms sort above optional terms regardless of order weight; equal weights sort alphabetically, uppercase before lowercase. (docs Settings_licenses; C15512, C3479)
16. A term cannot be both primary and deprecated. (en.json `customProperties.errors.primaryRetired`)
17. A deprecated term stays on existing licenses but is not offered for new ones and shows as `DEPRECATED: {name}`. (docs Settings_licenses; en.json `customProperty.retiredName`)
18. A term's Type cannot be changed after creation. (docs Settings_licenses)
19. Term names must be unique; a duplicate gets a 422 and the UI shows the backend message. (ERM-3229, ERM-3230, ERM-3977)
20. Term Name: letter first, then letters (Unicode allowed)/digits/underscores; enforced by UI and API. (C1385636, C1347204, ERM-3465)
21. A term in use on a license cannot be deleted; the UI shows `There was an error deleting term: {label}. {error}`. (ERM-3428; docs Settings_licenses)
22. Term visibility and notes need a term value first. (en.json `errors.termVisibilityWithoutValue`, `customPropertyNoteWithoutValue`)
23. Integer/Decimal terms accept a leading minus and `e` notation (e.g. `1e3`); decimals allow max 2 decimal places. (ERM-3184; en.json `errors.maxTwoDecimals`)
24. Removing one optional term card must not clear the value of another term in the same category. (ERM-3813)
25. Terms are grouped into one accordion per category (`Terms ({ctx})`). (en.json `terms.help.category`, `customProperties.defaultTitle`)
26. Deleting a license also deletes its amendments. (en.json `delete.confirmMessage`)
27. A license linked to one or more agreements cannot be deleted. (C196814; en.json `errors.noDeleteHasLinkedAgreements`)
28. Duplicate license lets the user pick sections (information, dates, internal contacts, organizations, core docs, terms, supplementary docs); duplicate amendment has no contacts/organizations and stays on the same license. (en.json `duplicate*Modal.*`; ERM-3979)
29. Duplicating requires view access to the source record; otherwise the API returns 403. (ERM-3958, ERM-3960)
30. Amendments can be created, edited, duplicated, deleted and searched independently; Add amendment / Edit / Duplicate / Delete in the UI require `UI-Licenses Licenses - Edit`. (cases — C10990–C10992, C196800, C415362; ViewAmendmentRoute.js)
31. Amendment terms supplement parent terms; conflicts require manual reconciliation. (github — earlier build, unverified this round)
32. Alternative names are searchable; an added but empty alternative-name row blocks save. (docs ERM/Licenses; cases)
33. Keyword search matches name, alternative names and description; the default search is filtered to Active and sorted by Name ascending. (stripes-testing `cypress/support/api/licenses.js`; C343046)
34. File download is a separate capability from edit. (package.json `ui-licenses.licenses.file.download`; cases)
35. Pick lists back specific dropdowns (`{Entity}.{FieldName}`) and Pick list terms; a new value is immediately selectable. (C464319, C464320, C464329)
36. A pick list applied to a term, or a value used on a license, cannot be deleted. (en.json `refdataCategory.deleteRefdataCategory.errorMessage`, `refdata.deleteRefdataValue.errorMessage`)
37. Picklists View capability must not allow creating pick lists. (ERM-3709)
38. Acquisition units are assigned to licenses only; amendments inherit them. (docs ERM/Licenses; ERM-3910; C1028993)
39. Being a member of any one of a license's acquisition units lifts that license's restrictions for the user. (C1029002, C1029004)
40. Restricted actions remain visible but greyed out and inactive (license Edit/Delete/Add amendment; amendment Edit/Delete/Duplicate). (ERM-3913, ERM-3914, ERM-3961, ERM-3979)
41. A view-restricted license is hidden from search and shows an access error when opened by URL. (C1028988; ERM-3962)
42. The `Acquisition unit` filter offers `No acquisition unit` as the first option. (ERM-3915, ERM-3916)
43. The license view hides the `Acquisition units` accordion when none are assigned. (ERM-3911; C1028998)
44. Linked agreements load in batches of 100. (C389580)
45. Tags icon and Tags filter are hidden when tags are disabled tenant-wide. (ERM-3704, ERM-3901)
46. CSV export uses camelCase column headers (`name`, `startDate`, …) and term columns `<term>`, `<term>:note`, `<term>:publicNote`, `<term>:internal`. (C10986; ERM-3874)
47. API error responses must not contain stack traces (unless `ENDPOINTS_INCLUDE_STACK_TRACE` is set). (ERM-3292, ERM-3741)
