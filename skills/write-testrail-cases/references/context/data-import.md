## What is Data Import

Data Import is the FOLIO app for batch importing records from external files (MARC 21, EDIFACT) into FOLIO. It creates and/or updates records in Inventory, MARC Authority, Orders, and Invoices apps. Two main areas: **Landing Page** (run imports, view logs) and **Settings** (configure profiles, file extensions, MARC field protections).

---

## Supported Record Types

### Can be Created AND Updated
- FOLIO Instances (Inventory)
- FOLIO Holdings (Inventory)
- FOLIO Items (Inventory)
- SRS MARC Bibliographic records
- MARC 21 Authority records

### Can be Created ONLY (not updated)
- FOLIO Orders and Purchase Order Lines
- FOLIO Invoices and Invoice Lines (EDIFACT)

### Cannot be Updated via Data Import
- SRS MARC Holdings records (create only)

## Profile Hierarchy (4 levels)

Recommended creation order: Field Mapping → Action → Match → Job

```
Job Profile  (top level — defines the full import workflow)
  ├── Match Profile  (optional — match incoming to existing records)
  │     ├── [if match found] → Action Profile → Field Mapping Profile
  │     └── [if no match] → Action Profile → Field Mapping Profile
  └── Action Profile  (without match — always applies)
        └── Field Mapping Profile
```

### Job Profile
- Entry point — user selects this when running an import
- Required fields: Name, Accepted data type (MARC or EDIFACT)
- Optional: Description, Tags
- Contains: linked Match profiles and/or Action profiles in an Overview accordion
- Match profiles can be **nested** to enable multi-field matching
- Action and Match profiles must exist before linking to a Job Profile
- Can be: edited, duplicated, deleted, tagged, exported/imported via API

### Match Profile
- Defines how incoming records are matched to existing FOLIO records
- Required fields: Name, incoming record format, existing record format, Match criteria (field + field)
- Since **Trillium** (UIDATIMP-1743): only **"Exactly matches"** is available as Match criteria — other criteria disabled
- Can match: Instance, Holdings, Item, MARC Bibliographic, MARC Authority
- Reusable across multiple Job Profiles
- Can be: edited, duplicated, deleted, exported/imported via API

### Action Profile
- Defines what action to take on the matched (or unmatched) record
- Required fields: Name, Action type, FOLIO record type
- Action types (exact UI text from source):
  - `Create (all record types except MARC Bibliographic, MARC Authority, or MARC Holdings)` [from source]
  - `Update (all record types except Orders, Invoices, or MARC Holdings)` [from source]
  - `Modify (MARC Bibliographic record type only)` [from source]
  - `Delete` — for MARC Authority only (new in **Umbrellaleaf**, UIDATIMP-1730 — shown last in the Action dropdown, only for no FOLIO record type selected or MARC authority; not present in en.json `selectAction.*`, which has only Create/Update/Modify) *(verify label in env)*
- FOLIO record types available depend on Action type selected
- Since **Trillium** (UIDATIMP-1328): when linking a Field Mapping Profile, the list is filtered to show only profiles matching the selected FOLIO record type
- Links to one Field Mapping Profile (optional but common)
- An action profile can only link to **one** field mapping profile
- Edits to an Action Profile are reflected everywhere it is used
- "Linked data" record type option was **removed** in **Trillium** (UIDATIMP-1755) — do not assert its presence
- Can be: edited, duplicated, deleted, tagged, exported/imported via API

### Field Mapping Profile
- Maps MARC/EDIFACT fields to FOLIO record fields
- Two subtypes:
  - **MARC Field Mapping** — for Inventory, Authority records
  - **EDIFACT Field Mapping** — for Invoices
- Required fields: Name, Record type
- Can be: edited, duplicated, deleted, tagged, exported/imported via API

## Import Flow

1. Staff uploads a MARC or EDIFACT file (browse or drag-and-drop)
2. File must have a registered extension (Settings → File Extensions) — if not, upload blocked
3. **Select job profile** window appears → staff select the appropriate profile
4. Profile details panel shows: Name, Accepted data type, Description, Tags, Overview (linked action/match profiles), previous jobs using this profile
5. Actions → Run → **Are you sure?** confirmation dialog → Run
6. Job appears in **Running** accordion with progress
7. Job completes → log row appears in Logs pane

## Landing Page Layout

### Left pane: Jobs
- Upload area (browse or drag-and-drop)
- **Running** accordion — currently running jobs with progress bar; can be collapsed
- Job profile selection window with search

### Central pane: Logs
Columns: File name, Status, Records, Job profile, Started running, Ended running, Run by, ID

- **Default view**: most recent logs for non-single-record imports
- Single Record Import logs hidden by default
- All columns sortable
- Actions → **View all** to see all logs including Single Record Imports
- Logs are **never deleted** unless a user with delete capability explicitly deletes them

## File Extensions (Settings)

Located in **Settings → Data Import → File Extensions**

- Controls which file formats are accepted for upload
- If a file has an extension NOT in the list → upload blocked before profile selection
- Each extension: extension value (e.g. `.mrc`, `.dat`), data type (MARC, EDIFACT), blocked/allowed status
- Can be: created, edited, deleted

---

## MARC Field Protections (Settings)

Located in **Settings → Data Import → MARC Field Protection**

- Fields listed here are NOT overwritten during record updates even if incoming record has different data
- Can protect an entire field or a specific field + subfield combination
- **System defaults (cannot be removed)** (ui-data-import `src/settings/MARCFieldProtection/MARCFieldProtection.js`: `suppressEdit`/`suppressDelete` for `source === SYSTEM`; fields `Leader`, `001`–`005`, `009` cannot be added as a user protection, `DISABLED_FOR_PROTECTING_FIELDS`):
  - `001` — FOLIO Instance HRID
  - `999 ff` — SRS record UUID (`$s`) and FOLIO Instance UUID (`$i`)
- User-defined protections: can be added, edited, deleted
- System default protections have Edit/Delete suppressed in the UI (`MARCFieldProtection.js` `suppressEdit`/`suppressDelete`); the earlier statement "if edited it cannot be reverted" is therefore moot for the UI (unverified for the API)
- Since **Trillium** (UIDATIMP-1699): users can **override** default field protections specifically within MARC Authority Field Mapping Profiles

## Single Record Import (from Inventory)

A special import path triggered from Inventory app (not from Data Import landing page):
- **Actions → Overlay source bibliographic record** — updates existing MARC bib from external Z39.50/SRU source
- **Actions → Find and save** (or Import) — imports a new record from an external source

Single Record Import behavior:
- Logs appear only in **View All** with "Inventory single record imports = Yes" filter
- Not shown in the default Logs pane view
- Uses dedicated system profiles that cannot be edited:
  - Inventory Single Record - Default Create Instance job profile
  - Inventory Single Record - Default Update Instance job profile
  - Inventory Single Record - Default match for existing SRS record
  - Inventory Single Record - Default match for no SRS record

## Common Verification Patterns

### 1. Profile Created → Detail View Shown

```
Action:   Click "Save as profile & Close" in the New [profile type] form
Expected: The [profile type] was successfully created.
          Detail view of the created profile is shown in the 3rd or 4th pane.
          Profile name appears in the profile list.
```

### 2. Import Job Completes → Log Entry Appears

```
Action:   Upload file, select job profile, click Actions > Run > confirm
Expected: Job appears in "Running" accordion with a progress bar.
          After completion, log entry appears in Logs pane with status "Completed"
          (or "Completed with errors").
          Log row shows: File name, Status, Records, Job profile, Started running,
          Ended running, Run by, ID.
```

### 3. Import Blocked by Unregistered Extension

See rule 9: upload of a file with an unregistered extension → `Import blocked` modal, `You cannot upload files with this file extension`, no job created.

### 4. Verify Match Profile Record Type Options (ECS)

```
Action:   On Member tenant > Settings > Data import > Match profiles > New
Expected: "New match profile" page opens.
          "Details" accordion shows: Instance, Holdings, Item, MARC Bibliographic,
          MARC Authority.
          Orders and Invoices NOT available on Member tenant.
```

### 5. Field Mapping Profile Filtered by FOLIO Record Type (Trillium+)

```
Action:   In Action Profile, select "Holdings" in "FOLIO record type*" field,
          click "Link Profile"
Expected: Only Field mapping profiles with FOLIO record type "Holdings" are displayed.
          Profiles of other record types are not shown.
```

## ECS / Multi-Tenant Notes

**47 ECS-enabled test cases** found in this section (sections: Consortia subsections under MARC Bib, MARC Authority, MARC Holdings).

### Tenant Setup
Preconditions use: **Central**, **Member 1**, **Member 2** tenants.

### ECS-Specific Business Rules
1. **Central tenant** can create Action/Field Mapping Profiles for all FOLIO record types including Order and Invoice (UIDATIMP-1679/1685/1700/1701, ui-data-import CHANGELOG).
2. **Member tenants** can only create profiles for: Instance, Holdings, Item, MARC Bibliographic, MARC Authority — Order and Invoice options are **not shown** (UIDATIMP-1546/1547/1553 "Adjust the record options in Central tenant …", CHANGELOG; verification pattern 4 below).
3. **"Default - Create Holdings and SRS MARC Holdings" job profile is hidden on Central tenant** (Trillium, UIDATIMP-1733, CHANGELOG).
4. **Sharing deleted instances** on Central should not produce errors (Ramsons test case title `No error appeared after sharing deleted instance`; case id not recorded).
5. **Updating shared records from Central** requires `Consortia Data-Import Central-Record-Update` capability; without it the update is blocked (Trillium test cases; C1621478; Cypress `capabilitySets.js` `uiConsortiaDataImportCentralRecordUpdate`).
6. **Affiliation switching** modal title: `Select affiliation`.

## Key Business Rules for Test Cases

> Source tags: (cases) = ≥3 case titles, (jira) = acceptance criterion/bug fix, (github) = source/changelog, (cases+jira) = confirmed in both, (karate)/(en.json)/(readme)/(confluence) as named. Numbering was made sequential on 2026-11-24 (it previously repeated 26–30); rules 1–34 keep their numbers; the second block formerly numbered 26–30 is now 35–39 and the former 35 is now 40; rules 41+ are new in this refresh.

1. **4-level profile hierarchy must be built bottom-up** — Field Mapping → Action → Match → Job; each level must exist before the next can reference it. (docs `Settings/Settings_data_import/settings_data_import.md` — "This field mapping profile must already exist to link to it"; case C385629 builds the stack in this order)
2. **Match profile is optional for Create flows** — a job profile that only creates records needs no match profile (docs.folio.org `Data import/jobprofiles.md`: match "Only needed if job profile operates on existing records"). An **Update** action profile cannot be saved in a job profile without a linked match profile: creating the job profile fails with `New record not created: ActionProfile id [action_profile_id] and action UPDATE requires linked MatchProfile` and the job profile is NOT created (C446086, MODDICONV-294). The earlier wording "if absent all incoming records are treated as new" is not supported by a source. (docs + cases C446086)
3. **Action profile links to exactly one field mapping profile** — cannot link multiple; changing the mapping requires editing or duplicating the action profile. (docs `Data import/jobprofiles.md`, `Settings/Settings_data_import/settings_data_import.md`)
4. **Field mapping profiles filtered by FOLIO record type in the link dialog** *(Trillium, UIDATIMP-1328)* — only profiles of matching type appear when linking to an Action Profile. (jira + cases)
5. **Only "Exactly matches" is available as Match criteria** *(Trillium, UIDATIMP-1743)* — other criteria are disabled/hidden. (jira)
6. **"Linked data" removed from FOLIO record type selector** *(Trillium, UIDATIMP-1755)* — do not assert its presence. (jira)
7. **Editing an Action Profile propagates everywhere it is used** — changes affect all Job Profiles containing it. (unverified — no source found; the Karate/Cypress and docs sources do not state it)
8. **System defaults cannot be reverted after editing** — always duplicate first; "cannot edit" profiles are fully protected; "can edit" profiles are editable but irreversible (irreversibility unverified). (cases; ui-data-import `src/utils/constants.js` default-profile ID lists, `ActionMenu/menuTemplate.js`)
9. **File must have a registered extension** — upload blocked at file selection if extension not in Settings → File Extensions; "Import blocked" modal shown before profile selection. (docs `Data import/_index.md` step 1 + `Settings_data_import.md` File extensions; en.json `Import blocked`)
10. **Single Record Import logs hidden by default** — only visible via Actions → View all + "Inventory single record imports = Yes" filter. (docs `Data import/_index.md` Logs and "Inventory single record imports" filter)
11. **001 and 999 ff fields are always protected** — cannot be overwritten on any update import; system-level protection, not removable in the UI. (ui-data-import `src/settings/MARCFieldProtection/MARCFieldProtection.js`; docs `Settings_data_import.md` MARC field protection)
12. **EDIFACT invoices/orders: Create only** — no Update action available for Orders or Invoices. (en.json `selectAction.update`: "Update (all record types except Orders, Invoices, or MARC Holdings)")
13. **MARC Holdings: Create only** — Data Import cannot Update existing MARC Holdings records. (en.json `selectAction.update` / `selectAction.create`)
14. **Completed with errors = partial success** — some records imported; error log shows which records failed and why. (docs `Data import/_index.md` "Troubleshooting failed imports")
15. **Failed status = no records created or updated** — clicking the row shows the error log; no record changes occurred. (docs `Data import/_index.md`; en.json `failed`; label `Fail` vs `Failed` — see Known Gaps)

## Data-Slicing — large-file chunking (confirmed — "DI TFT" subsection, C402385/C404412/C404413/C404414)

An infrastructure enhancement (`Data-Slicing`, gated by an env flag) that splits a large uploaded MARC file into **chunks/slices on the S3 server** before importing, then runs a data-import job per chunk.

- Slice size ≈ **1,000 records per chunk** (mod-data-import README default `RECORDS_PER_SPLIT_FILE=1000`; feature flag `SPLIT_FILES_ENABLED`, default `false`): a file of 1,001–2,000 records → **2 chunks**; exact-1-slice / <1-slice / 10-slice variants are each their own case (C404412/C402385/C404414). The split is done "according to the cluster settings" and each chunk's content sums back to the incoming file.
- These are **backend/infra cases** (Test Group Backend): preconditions require **S3 server access** + the `Data-Slicing` enhancement enabled; verification downloads the chunks from S3 and confirms the split is correct and a data-import ran for every chunk.

## Authoring style (measured 2026-07-23)

Data Import is large (~900 cases), ~52% `Functional` / ~47% `Other`, median **~10 steps** with ~35% of cases ≥15 steps — the biggest workflow cases outside Bulk Edit. The heavy cases live in the **"End to end scenarios"** section: full import flows that create/update Instance+Holdings+Item, modify a MARC bib record (C345423 is 46 steps), or match on 001 / 999 ff — each builds the full job/action/match/mapping profile stack in **Preconditions** (see the UIOR-1530-style bundling in MODINVSTOR-1577 cases) and then walks the whole upload→match→result→verify-record flow in one long case. Match this: rich profile setup in preconditions, a long single flow, verify every touched record (Instance accordion, quickMARC, linked Authority counts) at the end. Settings/log/permission cases stay short and `Other`.
